# Архитектура

SwiftUI/AppKit app → AudioCapture → CAF parts + journal → live rolling ASR → nonactivating NSPanel.

При остановке: закрытие файлов → восстановление единой временной шкалы → окна ASR с контекстом по краям и отбором слов по времени → разделение участников системной дорожки → группировка слов → локальная редактура → версия в SQLite → вставка в исходное поле.

Core отделён от App: `SpeechEngine`, `TextEngine`, `SpeakerEngine`, `ModelInstaller`, `AudioFiles`, `Store`. Модели управляются внутри процесса. ASR и редактор сериализуют доступ; записи на диск идут в отдельной последовательной очереди. UI получает только события/текст. Нет растущей очереди промежуточных ASR-запросов; сохраняется ограниченный хвост аудио, а окончательное распознавание использует файлы.

Загрузка моделей — отдельная явная операция с закреплённой ревизией, проверкой размера и SHA-256/Git blob SHA-1. Частичные загрузки возобновляются через URLSession resume data. Сетевые загрузки FluidAudio при обычной работе отключены.

Сессия содержит тип, исходные сегменты с временными отметками/источником/участником, версии обработки, именованные профили, состояние работы и закрепление. Запись сессии и FTS-документа выполняется одной SQLite-транзакцией. После сбоя незавершённые сессии видны как восстанавливаемые; повторная обработка запускается пользователем, чтобы не нагружать Mac неожиданно.

Поиск использует FTS5 Unicode и извлечение подходящих реплик. Вопрос/источники передаются локальной модели с запретом добавлять отсутствующие факты. Поиск не является полной семантической базой и может не находить перефразированные запросы без общих слов.
