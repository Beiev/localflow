# План LocalFlow

## Выполнено в 0.5.0 — 26 октября 2026

Архив открыт своему ассистенту: `localflow-mcp` лежит внутри бандла и говорит по MCP через stdio — четыре инструмента только на чтение (найти записи, перечислить, прочитать одну, найти моменты по словам с отметками, именем говорящего и записью). Инструмента, который что-то меняет, в сервере нет. Подключение — в [mcp.md](mcp.md).

Приложение замечает начатый созвон: микрофон занят не им дольше полуминуты и запущено приложение для созвонов — предлагает записать строкой в окне и пунктом в меню. Запись само не начинает никогда; выключается одним тумблером.

Имена участников можно взять из встречи в календаре — для первого созвона с человеком, где обращений по имени ещё нет. Календарь читается только по нажатию, только для встречи, с которой пересекается запись, и только на чтение. Отображаемое имя важнее адреса: иначе один человек приходил дважды, «Лена Иванова» и `lena@example.com`.

Конспект созвона можно класть копией в выбранную папку — Markdown с датой в имени, перезаписывается только при изменении; текста с экрана в копии нет. Поиск по архиву сравнивает основы слов, а не слова целиком: «решение» теперь находит «решения».

В каталог добавлен второй проверенный вес редактора — Qwen 3.5 9B 4-bit, выбирается в настройках. `LOCALFLOW_EDITOR` подменяет вес для замера, не трогая настройку приложения.

Открытое по этому направлению: предложение записать созвон видно только в окне и в меню — в полноэкранном Zoom его не увидеть, для этого нужна панель у выреза, а её состояние трогать рискованно. Имена из календаря не сопоставляются с голосами автоматически. Поиск по архиву — полнотекстовый, без эмбеддингов: вопрос другими словами ничего не найдёт.

## Выполнено в 0.4.1 — 26 октября 2026

Конспект созвона читается по темам. Четвёртая ступень группирует уцелевшие записи в куски разговора, из которых они пришли — подряд по времени и по общим словам, — модель только называет группу в два-четыре слова, а абзац на тему собирается кодом: сначала что решили, потом что измерили, каждое предложение со своей отметкой. Группа, которую не удалось назвать, озаглавлена временем. Одна тема означает весь разговор, поэтому документ остаётся прежним. Добавлено письмо после созвона: темы, задачи строками и то, что осталось без ответа, собранные из уже готового документа, без отметок времени и без обращения к модели. Вопрос, на который ответили через пару реплик, больше не считается открытым. Ограничение раздела распределяется по записи: половина мест уходит по весу, остальные — тем кускам разговора, за которые ещё никто не сказал.

Интерфейс: вкладки и кнопка копирования закреплены сверху и не уезжают с текстом, ширина текста ограничена читаемой колонкой, заголовки получили воздух и полный контраст.

По итогам кросс-модельного ревью 0.4.0 исправлено тринадцать дефектов — список в [CHANGELOG](../CHANGELOG.md). Главные: правка больше не сливается с тем, что она исправляет («лимит десять тысяч» и «лимит двадцать тысяч» различались одним словом, а «не» для меры пересечения — стоп-слово); исполнитель и срок не уходят к чужой задаче; с экрана нельзя получить решение или задачу, только наблюдение; исполнитель сопоставляется целиком, а не по префиксу; цена не становится задачей.

Открытое по этому направлению: чтение экрана по-прежнему ни разу не запускалось живьём, и первый прогон за владельцем. Чтение экрана снимает весь дисплей без окон самого LocalFlow, а не только окно созвона — сузить это до одного окна можно только вторым потоком, и это решение не принято. Чистота разделов теперь считается тем же правилом, которым раздел и выбирается, поэтому она — остаток, а не независимое мнение.

## Выполнено в 0.4.0 — 26 октября 2026

Сжатие созвона переведено на три ступени: реплики с устойчивыми номерами → типизированные записи по окнам разговора → сборка документа кодом. Модель не видит часов и поэтому не может выдумать отметку; владельца задачи принимает только совпадение с известным говорящим; разделы собираются по типу записи, а не по усмотрению модели; вступление собирается в коде. Качество измеряется прокси-метриками (`SummaryQuality`), старый однопроходный путь сохранён для сравнения (`summary-ab`). Добавлено чтение показанного экрана: текст и заголовки окон, моменты с началом и концом, свои номера для цитирования, раздел «Что показывали» и вкладка «Экран»; по умолчанию выключено. 199 тестов ядра и 16 интерфейсных проходят.

Открытое по этому направлению: конспект по-прежнему набор разделов без связного разбора по темам, поэтому сюжет разговора в нём не читается — это главный разрыв с эталоном, который задал владелец. Отбор при ограничении разделов идёт по весу записи, а не по значимости для разговора. Открытым вопросом считается всё, что модель так назвала, включая вопросы, на которые ответили сразу. Чтение экрана ни разу не запускалось живьём: это запись настоящего экрана владельца, и первый прогон — за ним; поэтому нет замеров диска, нагрузки и качества распознавания русского текста с экрана.

## Дальше — по порядку

Поле конкурентов по созвонам, их чтение экрана и порядок работы — в [competition-2026-10.md](competition-2026-10.md). Сделано в 0.4.1: разбор по темам, письмо после созвона, закрытие отвеченных вопросов, распределение ограничения по записи. Осталось по порядку:

1. Первый живой прогон чтения экрана. Это настоящий экран владельца, поэтому прогон за ним; он даёт размер журнала за час, время распознавания кадра и ответ про русский текст с экрана. Там же решается, сужать ли захват до одного окна вторым потоком.
2. Выбор веса модели на уже готовом стенде `summary-ab`. Кандидат из разбора — Qwen3.5-9B-4bit, около 5,98 ГБ весов против Gemma 4 E2B сейчас, на машине с 18 ГБ, где одновременно живут Parakeet и диаризатор. Сравнивать точность извлечения по окну, а не вид документа.
3. Календарь как источник имён: на первом созвоне с человеком обращений по имени ещё нет, а предлагать имя всё равно нужно.
4. MCP над архивом: свои созвоны с цитатами из любого ассистента, локально.

## Выполнено в 0.3.9 — 25 октября 2026

Созвон теперь читается, а не только пересказывается: вкладки «Конспект / Расшифровка / Исходник», разметка рисуется как разметка, отметки `[мм:сс]` открывают запись, каждая вкладка копируется отдельно. Добавлен режим чистой расшифровки с проверкой сохранности реплик. Голоса, у которых меньше 5% речи и меньше минуты, сводятся к соседнему; имена участников предлагаются по обращениям в самой записи и применяются одним кликом. 116 тестов ядра и 16 интерфейсных проходят.

Что осталось открытым по этому направлению: конспект не содержит связного разбора по темам — только разделы из типизированных записей, поэтому сюжет разговора в нём не читается; выбор при ограничении разделов идёт по весу записи, а не по значимости для разговора; ограничения по ASR, онбординг и публичная поставка не тронуты. Интерфейс 0.3.9 не проверялся глазами: доступа к экрану в той сессии не было.

## Выполнено в 0.3.3 — 16 сентября 2026

Установлены защита редактуры для русских/английских отрицаний и неоднозначных чисел, единый безопасный выбор текста для диктовки во время созвона, объяснения откатов, локальные замеры задержки, миграции архива с резервной копией и защитой от новой схемы. Добавлены документация участника и конфигурация CI; 78 тестов проходят. Доказательства и ограничения — в [validation.md](validation.md), команды — в [diagnostics.md](diagnostics.md).

Следующий приоритет — оценочный корпус с ручным эталоном: отдельно ошибки распознавания, сохранение смысла редактором и время до вставки. На нём сравнивать ASR и принимать решения о коротком пути без LLM. Первый холодный replay занял 22,69 с, повторный в новом процессе 4,99 с, прогретые 1,48–1,50 с: нужна отдельная работа над первым запуском. UI-пагинация, лёгкие контрольные сохранения транскрипции, смена аудиоустройств, онбординг и публичная поставка остаются открытыми; наличие миграционного раннера не означает выполнения всей фазы данных из хендофа.

Целевой компьютер: Apple M3 Pro, 18 ГБ, macOS 26. Нативное приложение на русском языке, локальные модели без подписок и платных API. Интернет нужен для явной загрузки моделей.

## Реализованные контуры первой версии

- Диктовка по левому ⌘B, отмена Escape, неактивирующее плавающее окно, живые гипотезы и сегменты с временными отметками, отдельная финальная редактура. Сохранение результата при неподтверждённой вставке и восстановление буфера обмена.
- Заметки: запись, пауза, импорт аудио, исходник и версии, связный текст / резюме / ТЗ / задачи, редактор, прослушивание фрагментов, экспорт Markdown/TXT.
- Созвоны: выбранное приложение через ScreenCaptureKit, микрофон отдельно, разделение голосов после записи, ручные имена и явно сохраняемые голосовые профили. Известное число собеседников можно указать; по умолчанию оно определяется автоматически.
- SQLite и полнотекстовый поиск, личный словарь подтверждённых исправлений, ответы по найденным исходным репликам с источниками.
- Части аудио на диске, восстановление незавершённой обработки, приоритет диктовки над фоновой обработкой, выгрузка моделей после простоя. Аудио 30 дней, закреплённое бессрочно, тексты до удаления.

Наличие реализации не означает прохождение всех проверок: фактические результаты и оставшиеся ограничения приведены в [validation.md](validation.md).

## Приёмка

1. На 40 контрольных записях сравнить 8/4-bit и Handy: русский, англицизмы, числа, даты, отрицания, самокоррекции, паузы. Синтетический набор — предварительная проверка; речь владельца обязательна.
2. На реальном микрофоне измерить первые слова и p95 отставания (цель ≤2 с), финальную обработку диктовки до 30 с (цель ≤5 с). Отдельно измерять первую подготовку CoreML и повторную загрузку из кеша.
3. Проверить полные экраны, несколько мониторов, фокус, буфер обмена, TextEdit, браузер, Telegram и Codex. Убедиться, что сообщение никогда не отправляется автоматически.
4. Проверить Meet в Chrome, Zoom, Telegram в наушниках, двух и четырёх участников, перебивания, неизвестные голоса, ручное исправление имён. Двухчасовой реальный созвон без пропусков и линейного роста памяти.
5. Проверить запрет сети, разрешения, отключение микрофона, сон, недостаток диска, принудительное завершение и перезапуск. Удалённые записи должны исчезать из поиска.

## Последующие этапы

Календарь, Slack, MCP, автоматическое обнаружение созвонов, мобильные приложения, корпоративные функции. Качество русского словаря, ASR и сопоставления голосов улучшается по реальным контрольным примерам, без скрытого наблюдения за вводом и без автоматического импорта личного архива.
